# ESP32-P4-Function-EV-Board: Board-Support Fact Sheet for a Bare-Metal Rust Kernel

Date: 2026-10-28 · Chip: ESP32-P4 rev v1.0 · Scope: I2C/GT911, SD (SDMMC), audio (ES8311/I2S), Ethernet (EMAC/IP101), Wi-Fi (C6 over SDIO/ESP-Hosted), GPIO matrix, buttons/LEDs.

## Executive summary

- **I2C**: The board uses I2C1 on SCL=GPIO8 and SDA=GPIO7, with 2.2 kΩ external pull-ups. It carries the ES8311 at 7-bit address 0x18 and the GT911 at 0x5D. The GT911 INT and RST lines are **not wired to the P4**, so touch input must be polled.
- **SD card**: The card sits on SDMMC **slot 0**, a 4-bit bus on **dedicated IO_MUX pins** (function 0): CLK 43, CMD 44, D0–D3 39–42.
  - **LDO channel 4 (ESP_LDO_VO4) must be on at 3.3 V.** It powers the 51 kΩ pull-ups on the SD lines, and most likely the pad bank as well. The `voltage 0` warning in the log is harmless: IDF acquires the channel at 0 mV and sets 3300 mV later.
  - The card's own VDD comes from a P-FET switched by **GPIO45 (SD_PWRn, active-low)**. It is pulled low by default, so the card is powered unless you drive GPIO45 high.
- **Audio**: I2S1 with MCLK=13, BCLK=12, WS=10, DOUT=9 and DIN=11. The amplifier enable (NS4150B CTRL) is **GPIO53, active-high**. The ES8311 runs in slave mode and needs MCLK = 256·fs = 11.2896 MHz.
  - From the 40 MHz XTAL, the I2S1 TX divider is N=3, x=1, y=33, z=175, yn1=1, which gives 11.289609 MHz. The BCK divider is 8.
- **Ethernet**: There is an RJ45 port and an **IP101GRI at PHY address 1**. The RMII pins are TXEN 49, TXD0 34, TXD1 35, CRS_DV 28, RXD0 29, RXD1 30, with MDC 31 and MDIO 52. PHY reset is GPIO51 (active-low).
  - The **50 MHz REF_CLK is generated by the PHY** (from its 25 MHz crystal) and enters the P4 on GPIO50. In IDF terms this is `EMAC_CLK_EXT_IN`.
- **Wi-Fi**: The ESP32-C6 is wired to SDMMC **slot 1 through the GPIO matrix**: CLK 18, CMD 19, D0 14, D1 15, D2 16, D3 17, 4-bit at 40 MHz.
  - C6_EN is GPIO54 (pulse high, low, high to reset) and C6_WAKEUP is GPIO6.
  - ESP-Hosted uses a 12-byte header, CMD53 to fixed SDIO addresses, and protobuf RPC inside TLV frames on the serial interface. It is the largest piece of work here.
- **Buttons and LEDs**: BOOT is GPIO35 (10 kΩ pull-up, active-low, and also the boot strap). RESET goes to the chip EN pin. There is **no user LED**, only a red power LED and the RJ45 LEDs driven by the PHY.

**Source quality.** Pin facts are cross-checked between the Espressif BSP, IDF/ESP-Hosted Kconfig defaults, and the **v1.5.2 board schematic** (`dl.espressif.com/dl/schematics/esp32-p4-function-ev-board-schematics_v1.52.pdf`). All three agree. Register facts come from the IDF v5.5 HAL/LL and SoC headers, which are vendor-authoritative.

## (a) I2C bus and GT911 touch

**Bus.** I2C1 is the BSP default (`Kconfig:10-14`) and the schematic is port-agnostic, so any port works. I2C1 sits at 0x500C5000. The I2C clock comes from the 40 MHz XTAL. The GT911 driver runs at 100 kHz (`ESP_LCD_TOUCH_IO_I2C_GT911_CONFIG`). The log warning "Please check pull-up resistances" only means internal pull-ups were not enabled; the board has 2.2 kΩ external pull-ups.

**Device addresses (7-bit):**
- ES8311: **0x18**. The codec's CE pin is pulled down (R57 10 kΩ to AGND). `ES8311_CODEC_DEFAULT_ADDR` is 0x30 in 8-bit form (`device/include/es8311_codec.h:18`), and the I2C layer shifts it right by one (`platform/audio_codec_ctrl_i2c.c:52`).
- GT911: **0x5D**, with 0x14 as the alternative (`esp_lcd_touch_gt911.h:42-43`). The board's INT and RST lines are **NC** (BSP h:92-97), so the address is whatever the LCD board straps it to. The BSP uses 0x5D and the original firmware read ID "911" there.

**Bring-up (register level; the controller is Espressif's own design, not DesignWare):**
1. Enable the clocks and pulse reset:
   - Set `HP_SYS_CLKRST.soc_clk_ctrl2.reg_i2c1_apb_clk_en` (0x1C bit 13).
   - Set `peri_clk_ctrl10.reg_i2c1_clk_en` (0x40 bit 27) and `reg_i2c1_clk_src_sel=0` (XTAL).
   - Pulse `hp_rst_en1.reg_rst_en_i2c1` (0xC4 bit 21) (`hal/esp32p4/include/hal/i2c_ll.h:141-163, 841, 925`).
2. Set the clock divider in `peri_clk_ctrl11.reg_i2c1_clk_div_num` (= clkm_div−1). Then set the SCL low/high periods, `sda_hold`, `sda_sample`, the start/stop setup and hold times, and the timeout (`i2c_ll.h:174-205`). Finish with `ctr.conf_upgate=1` (`i2c_ll.h:129`).
3. Configure CTR (0x04): `ms_mode` bit 4 = 1, `sda_force_out`/`scl_force_out` bits 0/1 = 0 (open-drain), `clk_en` bit 8 = 1.
4. Route the pins through the GPIO matrix. Signals are I2C1_SCL 70 and I2C1_SDA 71, used for both in and out (`gpio_sig_map.h:145-148`). Set `GPIO_PINn.pad_driver` bit 2 = 1 (open-drain) and enable input (FUN_IE).
5. Run a transfer:
   - Write bytes to the TX FIFO (`DATA` 0x1C, or the FIFO window at +0x100).
   - Fill `COMD0..7` (0x58..0x74) with `{byte_num[7:0], ack_en b8, ack_exp b9, ack_val b10, op_code[13:11], done b31}`. Op codes: RSTART=6, WRITE=1, READ=3, STOP=2, END=4 (`i2c_ll.h:30-48`).
   - Set `ctr.trans_start` (bit 5) and poll `INT_RAW` (0x20) for trans_complete or nack.

**GT911 register map** (16-bit big-endian register address, sent as a 2-byte write and then a read; `esp_lcd_touch_gt911.c:23-27, 220-290`):

| Reg | Use |
|---|---|
| 0x8140..0x8142 | Product ID ASCII "911" (0x39 0x31 0x31, matching the log) |
| 0x8047 | Config version |
| 0x814E | Status: bit 7 = buffer ready, bit 4 = key pressed, bits [3:0] = number of touches (0..5) |
| 0x814F + 8·i | Point i: `[track_id, xL, xH, yL, yH, sizeL, sizeH, reserved]` |
| 0x8093 | Key states |
| 0x8040 | Command register (0x05 = sleep) |

**Poll loop:** read 0x814E. If bit 7 is set and the count is between 1 and 5, read `count*8` bytes from 0x814F. **Always write 0x00 to 0x814E afterwards**; otherwise the GT911 stops updating. The BSP flips both axes for the panel (`mirror_x=1, mirror_y=1`, BSP .c:847-851).

**LDO4 register programming.** LDO channel 4 is unit 3, which maps to PMU `ext_ldo[4]` (`ldo_ll.h:34, 154-219`). The two registers are `PMU_EXT_LDO_P1_0P2A_REG` = 0x50115000+0x1D8 and `…_ANA_REG` = +0x1DC (`pmu_reg.h:4440, 4508`).
- For 3.3 V, the IDF path does `tieh=1` (rail bypass, bit 14), `force_tieh_sel=1` (software owner, bit 7), `tieh_sel=0` (bits 11:9), `en_vdet=1` (ANA bit 26), and then `xpd=1` (bit 8).
- For 1.8 V you would instead program `dref` (ANA bits 31:28) and `mul` (ANA bits 25:23) using the eFuse-calibrated search in `ldo_ll_voltage_to_dref_mul`.

**Clocking on P4.** The first-stage divider is **not** in the SDMMC block. It lives in `HP_SYS_CLKRST` (`sdmmc_ll.h:140-280`):
1. Enable the bus clock with `soc_clk_ctrl1.reg_sdmmc_sys_clk_en` (0x18 bit 14). Pulse `LP_AON_CLKRST.hp_sdmmc_emac_rst_ctrl.rst_en_sdmmc` (0x50111000+0x4C).
2. Select the source with `peri_clk_ctrl01.reg_sdio_ls_clk_src_sel = 0` (PLL_F160M) and set `reg_sdio_ls_clk_en = 1`. Source 1 is SDIO_PLL 200 MHz, used only for UHS.
3. Divide by N with `peri_clk_ctrl02`: `edge_h = N/2−1`, `edge_n = N−1`, `edge_l = N−1`, then pulse `edge_cfg_update`. For N=1, set `reg_sdio_hs_mode=1` and all edge fields to 0.
4. Set phase: `peri_clk_ctrl02.reg_sdio_ls_drv/sam/slf_clk_en = 1`, `drv_clk_edge_sel = 1`, `sam = 0`, `slf = 0`, then update.
5. The card divider is set inside DWC: `CLKSRC.card0 = 0` and `CLKDIV.clk_divider0 = M`, giving the card clock 160 MHz/N/(2M), or no further division if M=0.

| Rate | Host div N | Card div M | Result | Source |
|---|---|---|---|---|
| Probe | 10 | 20 | 400 kHz | `sdmmc_host.c:220-283` |
| Default speed | 8 | 0 | 20 MHz | same |
| High speed (BSP uses `SDMMC_FREQ_HIGHSPEED`) | 4 | 0 | 40 MHz | same |

**Init order** (`sdmmc_host.c:496-570, 634-830`):
1. Enable the bus clock and pulse reset. Set host div N=2 so registers are reachable.
2. Set `CTRL.controller_reset | fifo_reset | dma_reset` (bits 0, 1, 2) and wait for them to self-clear.
3. Write `RINTSTS = 0xFFFFFFFF` and `INTMASK = 0`, then enable the wanted bits and `CTRL.int_enable`.
4. Run DMA init: `CTRL.dma_enable=1`, `BMOD = 0`, then `BMOD.sw_reset=1`, then `IDINTEN.ni/ri/ti=1`.
5. Configure pads for GPIO 39-44:
   - IO_MUX `MCU_SEL=0`, FUN_IE=1, pull-down off, FUN_DRV=3.
   - IO_MUX register = 0x500E1000 + 4·(gpio+1) (GPIO0 is at +0x4; GPIO39 at +0xA0).
   - Hold D3 high as a GPIO until 4-bit mode is set, so the card enters SD mode rather than SPI.
6. Feed constants into the GPIO matrix for the slot-0 sideband inputs:
   - `SD_CARD_DETECT_N_1` (in-sig 126) = const 0 (0x3E), meaning the card is present.
   - `SD_CARD_WRITE_PRT_1` (130) = const 1 with invert (not protected).
   - `SD_CARD_INT_N_1` (128) = const 1 (0x3F) (`sdmmc_host.c:795-818`).
   - **If you skip this, CDETECT reads "no card"** and the IDF-style start check fails.
7. Set the card clock to 400 kHz and `CTYPE.card_width` bit 0 = 0 (1-bit).
8. Send CMD0 → CMD8 → ACMD41 (loop) → CMD2 → CMD3 → CMD9 → CMD7 → ACMD6 (4-bit). Then set `CTYPE.card_width` bit 0 = 1 and raise the clock.

**Issuing a command** (`sdmmc_host.c:421-480`):
1. Wait until `CMD.start_command` (bit 31) reads 0.
2. Write CMDARG.
3. Write CMD with `start_command=1`, `use_hold_reg=1` (bit 29), `card_num` (bits 20:16) = slot, `cmd_index` (bits 5:0), `response_expect` b6, `response_long` b7, `check_response_crc` b8, `data_expected` b9, `rw` b10, `send_auto_stop` b12, `wait_complete` b13, `send_init` b15 (for CMD0).
4. Wait for `start_command` to clear, then wait for `RINTSTS.cmd_done` (bit 2) or the error bits RTO/RCRC/RE, plus `data_over` (bit 3) for data commands.
5. **Clock-update pseudo-command:** CMD with `update_clk_reg=1` (bit 21), `wait_complete=1`, `start=1`. It is required after any change to CLKDIV, CLKSRC or CLKENA (`sdmmc_host.c:204-218, 301-352`). The sequence is: disable CLKENA → update → set dividers → update → enable CLKENA (`cclk_enable` and `lp_enable` bits per slot) → update.

**IDMAC descriptor** (`sdmmc_struct.h:8-41`). The descriptor is **64 bytes on P4** (16 words, padded to the L1 cache line):
- DES0: bit 1 = DIC, bit 2 = LD (last), bit 3 = FS (first), bit 4 = CH (chained), bit 5 = ER (end of ring), bit 30 = CES, bit 31 = OWN.
- DES1: bits 12:0 = BS1 (≤ 4096, a multiple of 4), bits 25:13 = BS2.
- DES2: buffer 1 pointer.
- DES3: next-descriptor pointer.

**DMA flow** (`sdmmc_host.c:1074-1145`):
1. Build a chain with CH=1, OWN=1, FS on the first descriptor and LD on the last.
2. Write the transfer length to BYTCNT and the block size to BLKSIZ.
3. Write the first descriptor address to DBADDR.
4. Set `CTRL.dma_enable=1`, `CTRL.use_internal_dma=1`, `BMOD.enable=1`, `BMOD.fb=1`.
5. Write any value to PLDMND, then issue the command.
6. Status arrives in IDSTS (TI/RI/NI). **Flush or invalidate the L1 cache** on descriptors and buffers, or place them in non-cacheable memory.

## (c) Audio: ES8311, I2S1 and the amplifier

**Hardware.**
- The ES8311 is a **mono** codec. Its DAC drives the NS4150B 3 W class-D amplifier; the BSP uses `pa_voltage=5.0` and `codec_dac_voltage=3.3`, so the hardware gain is −3.6 dB.
- I2S port: the BSP uses `CONFIG_BSP_I2S_NUM` (default 1, `Kconfig:30-35`). I2S1 sits at 0x500C7000.
- Mode: the codec is slave (`master_mode=false`, BSP .c:403) and uses MCLK (`use_mclk=true`). The P4 is I2S master.

**Pin routing (GPIO matrix outputs, from `gpio_sig_map.h:69-80`):**

| Signal | Pin | Matrix signal |
|---|---|---|
| MCLK | GPIO13 | out-sig 32 |
| BCLK | GPIO12 | out-sig 31 (`I2S1_O_BCK`) |
| WS | GPIO10 | out-sig 33 (`I2S1_O_WS`) |
| DOUT | GPIO9 | out-sig 34 (`I2S1_O_SD`) |
| DIN | GPIO11 | in-sig 34 (`I2S1_I_SD`) |
| PA enable | GPIO53 | plain GPIO output, set high after the codec is enabled |

**ES8311 register sequence for 44.1 kHz, 16-bit, slave, MCLK = 11.2896 MHz.** This reproduces esp_codec_dev `device/es8311/es8311.c` in the order `es8311_codec_new` → `esp_codec_dev_open` (set_fs, then enable) → set volume. Read-modify-write steps are shown with their resulting value assuming power-on defaults.

1. **open()** (`es8311.c:500-579`):
   - Read 0x0D; if it is not 0xFA, write `0D=FA`.
   - Write `44=08` twice (the driver works around a flaky first I2C write).
   - Write `01=30`, `02=00`, `03=10`, `16=24`, `04=10`, `05=00`, `0B=00`, `0C=00`, `10=1F`, `11=7F`, `00=80`.
   - `00`: clear bit 6 for slave mode, giving 0x80. This is the "Work in Slave mode" log line.
   - `01=3F` (MCLK pin as source, not inverted).
   - `06`: clear bit 5 (SCLK not inverted).
   - Write `13=10`, `1B=0A`, `1C=6A`, `44=58` (ADC/DAC reference; the default `no_dac_ref=false`).
2. **set_fs()** (`es8311.c:206-231, 169-204, 415-490`). Coefficient row `{11289600, 44100, pre_div 1, mult 1, adc_div 1, dac_div 1, fs_mode 0, lrck_h 0x00, lrck_l 0xFF, bclk_div 4, osr 0x10/0x10}` at `es8311.c:106`:
   - `09 |= 0x0C` and `0A |= 0x0C` (16-bit word length).
   - `09 &= 0xFC` and `0A &= 0xFC` (I2S Philips format).
   - Write `02 = 00`, `05 = 00`, `03 = 10`, `04 = 10`.
   - `07 = (07 & C0) | 00` and `08 = FF` (LRCK divider 256; only used in master mode).
   - `06 = (06 & E0) | 03` (BCLK divider, also master-only).
3. **enable() / start()** (`es8311.c:263-331, 620-667`):
   - Write `00=80` and `01=3F`.
   - `09 &= ~0x40` (DAC SDP unmuted).
   - Write `17=BF`, `0E=02`, `12=00` (DAC power), `14=1A` (bit 6 cleared, so analog mic), `0D=01` (power up), `15=40`, `37=08`, `45=00`.
   - Set **GPIO53 = 1**.
   - Unmute: `31 &= 0x9F`.
4. **Volume:** `32 = round((dB + 95.5) × 2)`, so 0xBF = 0 dB at the DAC and 0xFF = +32 dB (`es8311.c:145-157, 350-363`).
5. **Shutdown:** mute (`31 |= 0x60`), set GPIO53 = 0, then apply the suspend list at `es8311.c:243-261`.

**P4 I2S1 TX register bring-up.** I2S on P4 is DMA-only and fed by the **AHB GDMA**.
1. Clock gates:
   - `HP_SYS_CLKRST.soc_clk_ctrl2.reg_i2s1_apb_clk_en` (0x1C bit 15) = 1.
   - `LP_AON_CLKRST.hp_clk_ctrl.hp_pad_i2s1_mclk_en` (0x50111040) = 1.
   - Pulse `hp_rst_en2.reg_rst_en_i2s1_apb` (0xC8 bit 5) (`i2s_ll.h:125-165`).
2. TX clock:
   - `peri_clk_ctrl15.reg_i2s1_tx_clk_en` (0x54 bit 28) = 1.
   - `reg_i2s1_tx_clk_src_sel` (bits 30:29) = 0 for XTAL 40 MHz (1 = APLL, 2 = external).
   - `peri_clk_ctrl17.reg_i2s1_mst_clk_sel` = 1, so the MCLK pin follows TX (`i2s_ll.h:194-310, 407-445`).
3. MCLK fractional divider. MCLK = src / (N + b/a). For 40 MHz to 11.2896 MHz the accurate search (`hal_utils.c:69-111`) gives N=3, a=383, b=208, which yields 11,289,609 Hz (fs ≈ 44100.04 Hz).
   - Converted: yn1 = (2b > a) = 1, z = a−b = 175, x = a/z − 1 = 1, y = a mod z = 33 (`i2s_ll.h:624-640`).
   - **Write order matters** because of a double-division workaround (`i2s_ll.h:498-540`). First write `ctrl16.div_n=2`, `ctrl17.yn1=0`, `ctrl16.y=1`, `ctrl17.z=0`, `ctrl16.x=0`. Then write `ctrl17.yn1=1`, `ctrl17.z=175`, `ctrl16.y=33`, `ctrl16.x=1`, `ctrl16.div_n=3` (ctrl16 = 0x58, ctrl17 = 0x5C).
   - If you need an exact rate, use APLL as the source. Adds APLL bring-up work.
4. BCK: `TX_CONF.tx_bck_div_num` = 8−1 = 7, giving BCLK = MCLK/8 = 1.4112 MHz = 44.1k × 2 × 16 (`i2s_std.c:29-53`, `I2S_STD_CLK_DEFAULT_CONFIG` mclk×256, bclk_div 8).
5. Slot setup (`i2s_hal.c:147-176`, `i2s_ll.h:754-1050`):
   - Pulse `TX_CONF` (0x24) `tx_reset` b0 and `tx_fifo_reset` b1.
   - Set `tx_slave_mod=0`, `tx_tdm_en=1`, `tx_pdm_en=0` (STD mode is 2-slot TDM on HW v2), `tx_msb_shift=1` (Philips one-bit delay), `tx_ws_idle_pol=0`, `tx_mono=0`, `tx_left_align=0`, `tx_big_endian=0`, `tx_bit_order=0`.
   - `TX_CONF1` (0x2C): `tx_bits_mod=15`, `tx_tdm_chan_bits=15`, `tx_half_sample_bits=15`, `tx_tdm_ws_width=15`.
   - `TX_TDM_CTRL` (0x54): `tot_chan_num=1`, channel 0 and channel 1 enabled.
   - Then `tx_update=1` and wait for it to clear (`i2s_ll.h:687`).
6. AHB GDMA at 0x50085000:
   - Bus clock `soc_clk_ctrl1.reg_ahb_pdma_sys_clk_en` is on by default (bit 3). Reset via `hp_rst_en1` bit 1.
   - Set `OUT_PERI_SEL_CHn = 4` (I2S1; `gdma_channel.h:14`). Channel 0 registers: CONF0 0xD0 (rst b0, auto_wrback b2, eof_mode b3), LINK 0xE0 (outlink_start b1), PERI_SEL 0x100, OUT_LINK_ADDR 0x3B8. The channel stride is 0xC0 (`ahb_dma_reg.h`).
   - Descriptor format (12 bytes, `hal/include/hal/dma_types.h:21-38`): `{size[11:0], length[23:12], err_eof b28, suc_eof b30, owner b31}`, buffer pointer, next pointer.
   - For continuous playback, build a ring of descriptors.
7. Start: set `tx_start` (b2). Then initialise the codec, enable the PA, and unmute.

## (d) Ethernet: IP101GRI over RMII

**Board.** RJ45 J17 (HR913550A with magnetics) and an IP101GRI PHY (U8) with a 25 MHz crystal Y3. PHY pin 14 (RXCLK/50M_CLKO) outputs **50 MHz**, which feeds both the PHY TXCLK and P4 GPIO50.
- PHY address: straps "0b(0xx1)" give **1**. ethernet_init defaults to −1 (auto-scan), and the IDF driver checks OUI 0x90C3, model 5 (`esp_eth_phy_ip101.c:185-189`).
- Reset: active-low on GPIO51. Assert for 10 ms and wait 10 ms afterwards (`ip101.c:19-20`).

**IO.** All data pins use **IO_MUX function 3** (`emac_periph.c:33-130`, `io_mux_reg.h:335-495`). MDC and MDIO go through the GPIO matrix (out 108 MDC, out 109 MDO, in 107 MDI; MDIO is bidirectional on GPIO52).

**Clocking and reset** (`emac_ll.h:820-935`):
1. `HP_SYS_CLKRST.soc_clk_ctrl1.reg_emac_sys_clk_en` (0x18 bit 13) = 1. Pulse `LP_AON_CLKRST.hp_sdmmc_emac_rst_ctrl.rst_en_emac`.
2. RMII clock input:
   - `HP_SYSTEM.sys_gmac_ctrl0.sys_phy_intf_sel = 4` (RMII). **This must be set before the DMA software reset**, because the DWC core latches the interface on reset.
   - `peri_clk_ctrl00`: `reg_pad_emac_ref_clk_en=0`, `reg_emac_rmii_clk_en=1`, `rmii_clk_src_sel=0`, `rx_clk_en=1`, `rx_clk_src_sel=0`.
   - `peri_clk_ctrl01`: `rx_clk_div_num=1`, `tx_clk_en=1`, `tx_clk_src_sel=0`, `tx_clk_div_num=1`.
   - `LP_AON_CLKRST.hp_clk_ctrl.hp_pad_emac_txrx_clk_en=1`.
3. On link speed change, set the RX/TX divider: 1 for 100 Mbit (25 MHz), 19 for 10 Mbit (2.5 MHz) (`esp_eth_mac_esp.c:47-48, 230-246`).

**DWC GMAC registers.** MAC is at 0x50098000, DMA at 0x50099000, PTP at 0x50098700.

**Init sequence** (`esp_eth_mac_esp.c:532-589`, `hal/emac_hal.c:28-200, 523-543`):
1. Set the DMA bus-mode software reset and poll until it clears.
2. Set the MII-address CSR clock range from the APB frequency. With APB at 100 MHz, choose /62, which gives an MDC of about 1.6 MHz.
3. MAC defaults:
   - MACCR: watchdog and jabber on, IFG 96 bits, 100M, full duplex, IPC checksum offload, retry on, no CRC strip, back-off 10, preamble 7.
   - Frame filter: broadcast on, not promiscuous, block control frames.
4. DMA defaults:
   - OMR: drop TCP/IP checksum-error frames.
   - **RX store-and-forward OFF on P4** (the RX FIFO is only 256 B); TX store-and-forward OFF.
   - Flush the TX FIFO, set TX/RX thresholds to 64, enable OSF.
   - BMR: mixed burst, address-aligned beats, PBL=32 (`ETH_DMA_BURST_LEN_32`), **ATDS = 1 (enhanced 8-word descriptors)**, DSL = 0.
5. Write the MAC address registers. IDF reads the address from eFuse (`ESP_MAC_ETH`).
6. Program the RX and TX descriptor list base addresses.
7. Start in this order (it matters on this IP): enable interrupts and clear pending ones → MAC TE → DMA ST → DMA SR → MAC RE (`emac_hal.c:523-541`).
8. PHY: hardware reset, then BMCR reset and auto-negotiation through MDIO (MII address `{PA, GR, CR, GW, GB}`). Poll BMSR link status, then update the MAC speed/duplex and the RMII divider.

**DMA descriptor** (`hal/include/hal/emac_hal.h:56-187`). Enhanced format, 32 bytes, **padded to 64 bytes on P4** (`EMAC_HAL_DMA_DESC_SIZE` = 64, the cache line; Kconfig asks for 64-byte buffer alignment).
- **TDES0**: OWN b31, IC b30, LS b29, FS b28, DC b27, DP b26, TTSE b25, CRCR b24, CIC b23:22, TER b21, TCH b20, plus status bits.
- **TDES1**: TBS1 b12:0, TBS2 b28:16.
- TDES2: buffer pointer. TDES3: next descriptor. TDES6/7: timestamp.
- **RDES0**: OWN b31, AFM b30, FL b29:16, ES b15, FS b9, LS b8, plus status bits.
- **RDES1**: DIC b31, RBS2 b28:16, RER b15, RCH b14, RBS1 b12:0.
- RDES2/3: buffer and next pointers. RDES4: extended status. RDES6/7: timestamp.

## (e) Wi-Fi via the ESP32-C6 (ESP-Hosted over SDIO)

**Link facts** (esp-hosted-mcu v2.13.1 `Kconfig`, `P4_DEV_BOARD_FUNC_BOARD && CP_TARGET_ESP32C6`, matching schematic p5 SD2_* nets):

| Item | Value |
|---|---|
| Host slot | **1** (`Kconfig:715`; the help text says "Slot 1 connects to the on-board ESP32-C6") |
| Routing | GPIO matrix, slot-1 signals 0..5 (`SD_CARD_CCLK_2`, `CCMD_2`, `CDATA0_2`..`CDATA3_2`; `gpio_sig_map.h:8-18`) |
| Pins | CLK 18, CMD 19, D0 14, D1 15, D2 16, D3 17 |
| Pull-ups | 10 kΩ to 3V3 on the C6 side |
| Width / clock | 4-bit, 40 MHz (`Kconfig:778`) |
| Slot-1 clock divider | `CLKSRC.card1 = 1`, `CLKDIV.clk_divider1` (`sdmmc_ll.h:325-344`) |
| Matrix sideband constants | CD in-sig 127 = 0, WP 131 = const 1 inverted, INT 129 = 1 (same pattern as section b) |
| Reset | GPIO54 = C6 CHIP_PU, active-high. Sequence: drive high → 10 ms → low → 10 ms → high, then wait for C6 boot (`sdio_drv.c:1710-1720`; default is always reset on host boot, matching the log at L1794) |
| Wake line | GPIO6 = C6_WAKEUP (only needed for power save) |
| LDO | **Not needed** for slot 1; the internal-LDO option is off by default (`Kconfig:736-750`) |

**Protocol, enough to estimate effort:**
1. **SDIO card init**: CMD5 → CMD3 → CMD7. Then use CMD52 on function 0 to enable function 1 in CCCR 0x02, wait for CCCR 0x03 ready, set the interrupt enable in 0x04, set the 4-bit bus in 0x07, and write the function-1 block size of **512** into FBR 0x110/0x111 (`port_esp_hosted_host_sdio.c:125-210`, `sdio_reg.h:14-22`). The vendor/device IDs are 0x6666/0x2222 (`sdio_reg.h:89-91`).
2. **Slave registers** (function 1, CMD52/53, address = offset & 0x3FF, `sdio_reg.h:47-85`):
   - INT_ST 0x058, INT_CLR 0x0D4, PACKET_LEN 0x060 (20-bit cumulative byte counter), TOKEN_RDATA 0x044 (12-bit TX-buffer credit counter).
   - Host-to-slave interrupt: scratch 7 at 0x08C. Interrupt bits: new-packet = bit 23, throttle start/stop = bits 7/6.
3. **Data path**:
   - **TX**: check credits (`(TOKEN_RDATA − sent) mod 0x1000`), then CMD53 block/byte write of the frame to address **0x1F800 − len** (`ESP_SLAVE_CMD53_END_ADDR`; `sdio_drv.c:444-460, 760-801`).
   - **RX**: on an interrupt (DAT1 SDIO interrupt, or polling INT_ST), read PACKET_LEN, subtract the bytes already read (mod 0x100000), and CMD53-read that many bytes from 0x1F800 − len (`sdio_drv.c:486-560, 1340-1377`). v2 defaults to **streaming mode**, where one read can contain several packets.
4. **Frame header**: 12 bytes, packed, little-endian (`common/esp_hosted_header.h:13-34`). Payload size is ≤ 1536 per transfer.

   | Byte | Field |
   |---|---|
   | 0 | `if_type` (bits 3:0) and `if_num` (bits 7:4) |
   | 1 | flags (bit 0 = more fragments) |
   | 2-3 | len |
   | 4-5 | offset (= 12) |
   | 6-7 | checksum: byte sum of header + payload, computed with the checksum field zeroed |
   | 8-9 | seq_num |
   | 10 | throttle (bits 1:0) |
   | 11 | hci/priv packet type |

   Interface types: 1 = STA (raw 802.3 frames), 2 = AP, 3 = SERIAL (RPC), 4 = HCI, 5 = PRIV, 6 = TEST, 7 = ETH (`esp_hosted_interface.h:15-23`).
5. **Handshake**: the C6 sends a PRIV packet with type 0x33 (event) and event 0x22 (INIT), carrying TLV capabilities (chip id 0x0D = C6). The host answers with `HOST_CAPABILITIES` (0x44) and related config TLVs (`common/transport/esp_hosted_transport.h:27-66`).
6. **Control plane**: the SERIAL interface carries TLV `[0x01, len16 LE, "RPCRsp"/"RPCEvt"] [0x02, len16 LE, protobuf]` (`host/drivers/virtual_serial_if/serial_if.c:20-45`). The payload is protobuf `Rpc` messages from `common/proto/esp_hosted_rpc.proto` (2,479 lines). The minimum useful set is init, wifi_init, set_mode(STA), set_config, start, connect, the STA_CONNECTED/DISCONNECTED events, and get MAC. Data then flows as plain Ethernet frames on `if_type=1`, so the kernel needs its own IP stack (smoltcp fits).
7. **Firmware dependency**: the on-board C6 must run a matching ESP-Hosted slave build. The original log suggests it does. A v2 host against v2 slave firmware is the safe pairing; master is now v3.0.x and was restructured (`eh_*` names).

## (f) GPIO matrix and IO_MUX essentials

**Bases.** GPIO is at 0x500E0000 and IO_MUX at 0x500E1000 (`reg_base.h:112-114`, `esp32p4.peripherals.ld`). There are 57 GPIOs (0-56).

**IO_MUX pad register** at 0x500E1000 + 4·(n+1) (`io_mux_reg.h:12-70, 206`):

| Field | Bits |
|---|---|
| SLP_OE / SLP_SEL / SLP_PD / SLP_PU / SLP_IE | 0 / 1 / 2 / 3 / 4 |
| SLP_DRV | 6:5 |
| FUN_PD | 7 |
| FUN_PU | 8 |
| FUN_IE | 9 |
| FUN_DRV | 11:10 |
| MCU_SEL | 14:12 (function; **1 = GPIO/matrix**, 0 = SD slot 0, 3 = EMAC) |
| FILTER_EN | 15 |

Per-pin function numbers are the `FUNC_GPIOn_*` macros in `components/soc/esp32p4/register/soc/io_mux_reg.h`.

**Matrix registers** (`gpio_reg.h`, `gpio_struct.h:849-850`):

| Register | Address / layout |
|---|---|
| OUT_W1TS/W1TC | +0x08/+0x0C for GPIO0-31; +0x14/+0x18 for GPIO32-56 |
| ENABLE_W1TS | +0x24 (bank 0), +0x30 (bank 1); W1TC at +0x28 and +0x34 per the same pattern |
| IN | +0x3C, IN1 +0x40 |
| PINn | +0x74 + 4n: pad_driver (open-drain) b2, int_type b9:7, int_ena b17:13 |
| FUNC_IN_SEL_CFG[sig] | +0x158 + 4·sig: in_sel b5:0 (GPIO number, 0x3F = const 1, 0x3E = const 0), inv b6, **sig_in_sel b7 = 1 to route through the matrix** |
| FUNC_OUT_SEL_CFG[gpio] | +0x558 + 4·gpio: out_sel b8:0 (signal index; **256 = plain GPIO_OUT**), out_inv b9, **oen_sel b10** (1 = enable comes from GPIO_ENABLE, 0 = from the peripheral), oen_inv b11 |

**Routing recipe:**
- **Output:** set IO_MUX MCU_SEL=1, set `FUNC_OUT_SEL_CFG[pin] = sig` with oen_sel=0 for bidirectional peripherals (I2C, SDIO) or 1 plus ENABLE_W1TS for output-only signals.
- **Input:** set FUN_IE=1 and `FUNC_IN_SEL_CFG[sig] = pin | (1<<7)`.

**Signal index tables:** `components/soc/esp32p4/include/soc/gpio_sig_map.h`. For low-power pins the equivalents are `lp_gpio_sig_map.h` and `lp_iomux_reg.h`.

**ROM helpers (alternative):** `esp_rom_gpio_connect_out_signal` and `esp_rom_gpio_connect_in_signal`. They are callable only if the kernel links the ROM symbol table; doing the register writes directly is simpler.

## (g) Buttons and LEDs

- **BOOT** (SW2): GPIO35 to GND, 10 kΩ pull-up R208. Active-low and usable as a user button after boot. Holding it at reset selects download mode.
- **RESET** (SW1): drives ESP_EN (CHIP_PU). Not readable by software.
- **LEDs**: only a red power LED (schematic p6) and the RJ45 green/yellow LEDs driven by the IP101. **No GPIO-driven user LED.** The BSP sets `BSP_CAPS_BUTTONS 0` (h:52).

## Trade-offs and recommended bring-up order

| Subsystem | Hardware complexity | Kernel complexity | External dependency | Effort (1 engineer) | Rank |
|---|---|---|---|---|---|
| GPIO/IO_MUX + buttons | trivial | low | none | 0.5–1 d | 1 |
| I2C + GT911 polling | low | low | none | 1.5–2.5 d | 2 |
| SD (slot 0, PIO first, then IDMAC) + FAT (`embedded-sdmmc` or similar) | medium (LDO4, cache, CD constants) | medium | FAT crate | 5–8 d | 3 |
| Audio: ES8311 + I2S1 + AHB GDMA ring | medium (fractional divider, DMA) | medium | none | 4–6 d | 4 |
| Ethernet: EMAC + IP101 + smoltcp | medium-high (clock mux, cache-aligned descriptors) | medium-high | smoltcp | 7–12 d | 5 |
| Wi-Fi: slot-1 SDIO + ESP-Hosted + protobuf RPC + smoltcp | high | high (SDIO CMD52/53, streaming RX, credits, protobuf in `no_std`) | C6 firmware version lock; prost/micropb | 15–25 d (reuses the SDMMC host from SD) | 6 |

**Recommendation.** Build the SDMMC host once, with the slot as a parameter, and use it for both the SD card and the C6. Bring up Ethernet before Wi-Fi: it is deterministic, standard DWC IP with no co-processor firmware dependency, and it validates the smoltcp integration that Wi-Fi will reuse. Treat Wi-Fi as a separate milestone.

## Open risks

1. **Board revision.** Pins were verified against schematic v1.5.2. Boards from the chip-rev-v1.0 era are often v1.4, which differs in USB/UART and the IO24/25 headers; nothing found suggests the peripherals above changed, but this is not confirmed. Check the silkscreen.
2. **LDO4 pad-bank supply.** That VDD_IO for GPIO39-48 comes from ESP_LDO_VO4 is inferred from the schematic label "1V8/3V3(SDIO) ESP_LDO_VO4"; the pull-ups definitely do. If the ROM or 2nd-stage bootloader leaves LDO4 off, SD and the IO_MUX 39-48 pins will not work. Enable it explicitly.
3. **Cache coherency on P4.** SDMMC, EMAC and GDMA descriptors and buffers need 64-byte alignment plus writeback/invalidate (IDF calls `esp_cache_msync`), or must live in non-cacheable memory.
4. **I2S rate.** XTAL gives fs = 44100.04 Hz. That is fine for playback, but exact rates need APLL bring-up, which this research did not cover.
5. **ES8311 read-modify-writes.** The listed values assume power-on defaults for 0x06, 0x07, 0x09 and 0x0A. Keep them as read-modify-write in code.
6. **GT911 address.** The address is latched by INT at power-up, which is not under P4 control. Probe 0x5D, then fall back to 0x14.
7. **ESP-Hosted version lock.** The C6 firmware version is unknown. Host v2.x framing is described here; v3 (master) renamed and restructured things. Query the firmware version over RPC first, and plan for reflashing the C6 through the ESP-Prog header J2 if needed.
8. **Rev v1.0 specifics.** `ldo_ll_enable` has rev-dependent behaviour only for unit 0 (VO1). Nothing rev-gated was found in the SDMMC/EMAC/I2S/I2C LL code, but the TRM errata for v1.0 was not read.
